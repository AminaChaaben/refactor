Scenarios

Nine situations, nine entry points

Every real reason to reach into this module lands on exactly one of these.

"We've never run this through Refactor Radar."

Cold start on a new project

rrd-setup registers the module and writes config, then a full rrd-audit-all pass establishes the first tracked snapshot — no trend yet, and that's reported plainly rather than a fabricated 0/0/0.

rrd-setup → rrd-audit-all (full scan)
"I already suspect it's hardcoded config / bad locators."

Targeted single-detector run

Any of the ten detectors can be invoked standalone, scoped to the whole project or one file, without paying for a full ten-detector sweep.

a single rrd-detect-* skill, direct invocation
"CI just failed three times this week for no clear reason."

Real logs, unknown root cause

Aggregates full run history per test, classifies flaky vs. real vs. false-negative, then invokes the matching structural detector scoped to the specific flagged test — not a generic re-scan.

rrd-analyze-test-reliability → matching rrd-detect-*
"This suite barely runs — half the tests don't even execute."

Discovery or environment is broken

Diagnoses compile failures, discovery gaps, and environment blockers before any log analysis is possible — turns zero genuine runs into N real ones.

rrd-establish-execution-baseline → rrd-analyze-test-reliability
"We fixed a batch of findings last sprint — what's left?"

Repeat audit, scoped and compared

Offers an incremental scan restricted to files changed since the last run's commit, and reports Closed / New / Regressed against a capped 20-run history file — never silently defaults to incremental without stating the tradeoff.

rrd-audit-all (incremental mode)
"This same gap keeps showing up in every review."

One mistake vs. no convention

Reads a completed audit's findings and only escalates a gap type to a governance finding once it recurs three or more times across distinct files — one bad selector is a bug, four is a missing convention.

rrd-standards-audit (reads a prior rrd-audit-all report)
"Stop proposing, actually fix this one and prove it works."

Apply a diff for real

The only skill in this module permitted to touch source directly — re-reads the full current file before applying (proposals are written against a snapshot), runs the real test suite, and can auto-revert on a genuine regression if that's explicitly opted into.

rrd-apply-and-verify
"We want this blocking merges, not just advisory."

Wire the audit into a pipeline

A thin wrapper around a full audit: fails only on opportunities that are both new since the last run and at or above Critical — pre-existing debt doesn't block every build forever.

rrd-ci-gate → rrd-audit-all
"Get the top findings in front of the team as real tickets."

Export to a shared tracker

The only skill that writes to a system outside this project — requires two separate explicit confirmations (scope, then destination) before creating anything, and skips opportunities already exported.

rrd-export-tickets → GitLab issues
The one rule everything answers to

The Investigation Contract

evidence-and-diff-discipline.md — kept in sync across all fifteen detection/analysis skills
  1. No claim without a receipt — every finding cites the exact query_graph/search_graph/trace_path/log evidence that produced it.
  2. Source is never edited directly. Every fix is a diff written to the target project's own proposals/ — except rrd-apply-and-verify, invoked explicitly, per diff.
  3. Resolve the target project first, via list_projects/index_status, before querying anything.
  4. Confidence, not absolutes — every finding is high/medium/low, corroborated by real execution logs where available.
  5. Prefer get_code_snippet over a raw file read once the graph has narrowed to a candidate — cheaper, faster, and it carries precomputed metrics a plain read never will.
Module code rrd · config at _bmad/rrd/config.yaml · diffs always land in the target project's own proposals/, never here.
